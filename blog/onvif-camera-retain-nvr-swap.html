기존 IP 카메라는 그대로 두고 NVR만 바꾸는 교체 제안 방법Keep Your IP Cameras and Replace Only the NVR: How to Make the Proposal

2026.11.20
NVR 교체NVR Replacement ONVIF 카메라 등록Camera Registration 설치업체Installers NOX

건물에 ONVIF 카메라가 이미 설치되어 있는데, 고객이 "카메라는 그대로 두고 NVR만 바꿔 달라"고 요청하는 경우가 있습니다. 이른바 NVR 교체 제안입니다. 설치업체 입장에서는 반가운 요청이지만, 제안서를 쓰려고 하면 막히는 지점이 생깁니다. 카메라를 새로 들이지 않고 NVR만 교체할 수 있는지, 다른 대역에 있는 카메라는 어떻게 찾는지, 등록 과정이 복잡해 현장 시간이 늘어나지 않는지가 그렇습니다. 이 글에서는 기존 카메라를 살려 NVR을 교체하는 절차를 현장 순서대로 정리합니다.

기존 카메라가 교체 대상이 되는지 먼저 확인하세요

제안 전에 현장 카메라를 두 종류로 나눠 두면 작업 시간을 잡기 쉽습니다. NOX는 ONVIF Profile S·T를 지원하는 카메라를 검색으로 등록합니다. ONVIF를 지원하지 않는 카메라는 RTSP 주소를 직접 입력해 등록합니다. 수동 추가 화면에서 이름과 RTSP 주소는 필수이고, 사용자명과 비밀번호는 선택입니다.

카메라 종류등록 방법채널·스트림
ONVIF 카메라 (Profile S·T)ONVIF 검색 후 등록검색으로 채널과 스트림을 가져옴
ONVIF 미지원 카메라RTSP 주소를 직접 입력해 수동 추가채널과 스트림을 수동으로 추가

RTSP 카메라를 추가하면 "Main" 채널과 "main" 스트림이 카메라와 함께 만들어집니다. 카메라 수동 추가 화면의 RTSP 주소는 소문자 rtsp://로 시작해야 합니다. 대문자로 쓴 RTSP:// 주소는 저장은 되지만 영상이 나오지 않습니다. 주소에 공백이 필요하면 %20으로 인코딩해 입력합니다.

1단계: 자동 검색으로 같은 대역의 카메라를 찾습니다

현장에 가기 전에 카메라 기종과 대수, 각 카메라의 IP 주소 또는 대역, 관리자 계정을 먼저 정리해 두면 현장에서 다시 확인할 일이 줄어듭니다. 특히 카메라가 연결된 네트워크 인터페이스가 NOX에 물려 있는지 확인하세요.

ONVIF 카메라 검색은 카메라 추가 화면의 ONVIF 검색 탭에서 시작합니다. 기본 검색 방식은 자동 검색입니다. NOX의 물리 네트워크 인터페이스에서 멀티캐스트 WS-Discovery로 같은 서브넷의 카메라를 찾습니다. NOX 내부 전용 가상 인터페이스(컨테이너 브리지 등)와 연결이 끊긴 인터페이스에는 검색 요청을 보내지 않고 건너뜁니다. 자동 검색은 입력 칸이 없어서 검색 방식을 확인하고 검색 시작만 누르면 됩니다.

검색이 끝나면 결과는 세 가지 중 하나로 표시됩니다.

  • 카메라를 찾은 경우: 검색 결과 테이블이 나타납니다.
  • 성공했지만 0대인 경우: "발견된 카메라가 없습니다" 안내가 나타납니다.
  • 검색 자체가 실패한 경우: 붉은색 오류와 실패 사유가 나타납니다.

"0대"와 "검색 실패"는 다르게 표시되므로 원인을 나눠 볼 수 있습니다. 0대라면 카메라가 다른 서브넷에 있거나 멀티캐스트가 막힌 스위치 뒤에 있을 수 있습니다. 이때는 다음 단계인 IP 검색을 씁니다. 원인을 좁히려면 아래 순서로 점검합니다.

  1. 카메라가 NOX와 같은 네트워크에 있는지 확인합니다. 카메라가 붙은 네트워크 인터페이스가 NOX에 연결되어 있어야 자동 검색이 닿습니다.
  2. 카메라의 ONVIF 기능이 켜져 있는지 확인합니다.
  3. NOX와 카메라 사이의 방화벽 설정을 확인합니다.
  4. 결과가 "발견된 카메라가 없습니다"이면 검색은 정상이고 그 대상에 카메라가 없는 것입니다. 붉은색 오류 알림이 나왔다면 검색 자체가 실패한 것이므로 표시된 사유부터 봅니다.
  5. 검색 결과에 169.254.x.x 주소만 보인다면 카메라 네트워크 설정부터 고칩니다(아래 "현장에서 자주 막히는 지점은 이렇게 풉니다" 참고).

2단계: 라우터 너머 카메라는 IP 검색으로 찾습니다

IP 검색은 지정한 IP 주소로 검색 요청을 직접 보냅니다. 라우터 너머나 다른 서브넷에 있는 카메라, 멀티캐스트가 차단된 스위치 환경에서 씁니다. 검색 유형은 두 가지입니다.

  • 범위 검색(기본): 시작 IP와 끝 IP를 입력합니다.
  • 단일 검색: 카메라 IP 주소 하나를 입력합니다.

입력이 유효해야 검색 시작 버튼이 켜집니다. 버튼 아래에 대상 N개가 표시되므로 검색 전에 몇 개의 주소를 훑는지 확인할 수 있습니다.

현장에서 특히 신경 쓸 부분은 검색 대상의 크기입니다. 한 번에 검색할 수 있는 대상은 최대 254개, 즉 /24 서브넷 하나 분량입니다. 더 넓은 대역은 서브넷 단위로 나눠 여러 번 검색합니다. 예를 들어 10.0.0.1 ~ 10.0.15.254는 10.0.0.1 ~ 10.0.0.254, 10.0.1.1 ~ 10.0.1.254처럼 16번으로 나눠 검색합니다. 한 번에 너무 많은 주소를 훑으면 네트워크 장비의 ARP·이웃 테이블에 부담이 생겨 카메라의 응답이 유실될 수 있습니다.

IP 검색은 검색 과정에서 카메라 계정을 시도하지 않습니다. 지정한 IP에 ONVIF 검색 요청만 보내고, 응답한 카메라가 스스로 알리는 이름·제조사·모델 정보를 읽습니다. 사용자명과 비밀번호는 검색이 끝난 뒤 등록 단계에서 입력한 값만 사용됩니다.

IP 검색은 응답을 그대로 믿지 않습니다. 검색 대상 밖의 주소에서 온 응답은 무시되므로, 지정하지 않은 장치가 결과에 끼어들 수 없습니다. 카메라가 알려 준 접속 주소의 호스트가 실제 응답 주소와 다르면 실제로 응답이 온 주소를 씁니다.

IP 검색은 감사 로그에 검색 액션으로 남습니다. 검색 방식, 대상 수, 발견 대수와 함께 검색한 범위의 요약이 기록되므로 누가 언제 어떤 대역을 검색했는지 추적할 수 있습니다. 검색을 시작한 뒤 취소하거나 실패해도 기록이 남고, 입력 형식 오류나 대상 수 초과처럼 스캔이 시작되기 전에 끝난 요청은 기록되지 않습니다.

IP 검색은 서버 전체에서 한 번에 한 건만 실행됩니다. 다른 창에서 검색이 진행 중이면 "다른 검색이 진행 중입니다" 오류가 표시되므로 잠시 후 다시 시도합니다.

3단계: 등록하면서 채널과 스트림을 함께 가져옵니다

검색 결과 테이블에는 선택, 이름, IP 주소, 제조사, 모델, 사용자명, 비밀번호 열이 있습니다. 이름과 제조사·모델은 카메라가 스스로 알린 정보이고, 사용자명과 비밀번호 칸은 직접 입력하는 칸입니다. 등록할 카메라를 체크하고 카메라마다 계정을 입력합니다. 두 칸은 둘 다 입력하거나 둘 다 비워 두어야 합니다. 한쪽만 입력된 카메라가 있으면 등록이 시작되지 않고, 해당 카메라 이름과 함께 경고가 표시됩니다.

등록 화면의 모든 채널 및 스트림 자동 추가 옵션은 기본으로 켜져 있습니다. 이 옵션을 켜 두면 카메라를 등록한 뒤 채널과 스트림을 자동으로 검색해 추가합니다. 끄면 카메라만 등록되고 채널과 스트림은 나중에 직접 추가해야 합니다.

이미 등록된 카메라(같은 IP:포트)에는 노란색 중복 배지가 붙고 선택할 수 없습니다. 같은 카메라를 두 번 등록하는 실수를 막아 줍니다. 검색을 다시 시작하면 이전 결과와 선택, 입력해 둔 자격증명이 모두 지워지므로, 검색을 모두 끝낸 뒤에 계정을 입력하는 것이 안전합니다.

등록이 끝나면 카메라 목록의 상태 배지를 확인합니다. 온라인은 초록색, 오프라인은 빨간색, 오류는 회색으로 표시되며 약 10초 주기의 연결 점검 결과에 따라 실시간으로 바뀝니다. 새로 등록한 카메라는 새로고침 없이 첫 점검 주기 안에 온라인으로 바뀝니다. 배지가 온라인이라도 채널과 스트림이 실제로 생겼는지 확인하세요. 리소스 트리에서 카메라 노드를 펼치면 채널 목록이, 채널 노드를 펼치면 스트림 목록이 나타납니다. 라이브 화면에 영상이 나오는지까지 본 뒤 현장을 떠나는 것이 좋습니다.

카메라가 수십 대라면 카메라 목록 페이지의 카메라 가져오기 버튼으로 여러 대를 한 번에 등록할 수 있습니다. YAML 파일(.yaml·.yml)이나 카메라 내보내기 파일(.noxcam)을 끌어다 놓거나 선택하면 카메라 목록이 표로 나오고, 체크한 카메라만 등록됩니다. 템플릿 다운로드 버튼으로 YAML 양식을 받을 수 있습니다. 각 행에는 Valid, Invalid, Duplicate 배지가 붙으며, 유효하지 않거나 중복된 카메라는 선택할 수 없습니다. 중복은 IP·포트·RTSP URL로 판정하며, URL에 든 계정과 비밀번호는 비교에서 뺍니다. 계정만 다른 같은 주소는 중복입니다. 암호화된 .noxcam 파일에는 비밀번호가 들어 있지 않습니다. 비밀번호가 설정돼 있던 카메라는 비밀번호 재입력 필요 배지와 경고가 표시되므로, 가져온 뒤 다시 입력해야 합니다.

채널과 스트림을 직접 검색하는 방법

자동 추가를 껐거나 카메라의 설정(프로파일)이 바뀐 경우에는 직접 검색합니다.

  • 채널 검색: 리소스 트리에서 ONVIF 카메라에 마우스를 올리면 나타나는 검색 아이콘을 누르거나, 우클릭 메뉴에서 채널 검색을 고릅니다. 채널 검색 시작을 누르면 이름·해상도·FPS가 표시된 채널 목록이 나옵니다. 필요한 채널을 고르고 선택한 채널 생성을 누릅니다.
  • 스트림 검색: ONVIF 채널에서도 같은 방식으로 스트림 검색을 고릅니다. 프로파일마다 main·sub 타입, 해상도, FPS, 비트레이트, 코덱이 표시되며 Transport 기본값은 TCP입니다. 선택한 스트림은 하나씩 차례로 만들어지고, 일부가 실패해도 나머지는 계속 시도합니다.

스트림 검색 결과의 주소는 사용자명과 비밀번호를 가린 표시용입니다. 스트림을 만들 때 장비가 카메라에서 주소를 다시 받아 저장하므로, 검색 결과에는 카메라 비밀번호가 표시되거나 전송되지 않습니다. 대신 스트림을 만들 때는 카메라가 응답해야 합니다. 스트림 정보를 가져오지 못했다는 오류가 나오면 카메라 연결 상태를 확인한 뒤 다시 시도합니다. "카메라에서 선택한 스트림을 찾을 수 없습니다" 오류가 나오면 카메라 프로파일이 바뀐 것이므로 스트림 검색을 다시 해서 추가합니다.

현장에서 자주 막히는 지점은 이렇게 풉니다

  • 169.254.x.x 주소로 검색되는 카메라: 카메라가 DHCP를 받지 못해 스스로 정한 링크 로컬 주소입니다. NOX는 이 주소를 등록하지 않습니다. 카메라 제조사 도구나 카메라 웹 화면에서 장비 네트워크 대역의 고정 IP를 지정하거나 DHCP를 사용하도록 바꾼 뒤 다시 검색합니다. 카메라 쪽 설정을 한 번은 건드려야 할 수 있으므로, 제안 단계에서 미리 알려 두는 것이 좋습니다.
  • 등록할 수 없는 주소: 루프백(127.0.0.1, localhost), 0.0.0.0, 멀티캐스트 주소는 등록되지 않습니다. NOX 장비 자신의 주소에 media server 포트를 붙인 주소도 막힙니다. 이때는 "사용할 수 없는 주소입니다" 메시지가 표시됩니다.
  • 검색 대역에 검색할 수 없는 주소가 섞인 경우: 범위에 0.0.0.0, 멀티캐스트(224.0.0.0/4), 예약 대역(240.0.0.0/4)이 포함되면 검색 시작이 막히고 걸린 대역이 표시됩니다. 범위를 나눠 다시 입력합니다.
  • 스트림 주소 형식 오류: RTSP 주소는 소문자 rtsp:// 또는 rtsps://로 시작해야 하고, 공백과 제어 문자는 넣을 수 없습니다. http://로 시작하는 주소나 호스트 없이 경로만 쓴 값은 받지 않습니다.
  • 카메라 IP가 바뀐 뒤 영상이 끊긴 경우: 카메라를 삭제하고 다시 등록하지 마십시오. 삭제하면 녹화 영상이 영구 삭제됩니다. 카메라 편집에서 IP 주소를 장치의 새 주소로 바꾸고 주소 변경을 확인합니다. 카메라 IP가 자주 바뀌는 현장이라면 카메라에 고정 IP를 지정하거나 DHCP 서버에서 주소를 예약해 두는 것이 좋습니다.

발주처에게는 이렇게 설명하면 됩니다

발주처의 리테일·산업·빌딩 운영자는 기존 카메라를 살리는 방식이 현장에 무엇을 뜻하는지 궁금해합니다. 설치업체가 그대로 옮겨 쓸 수 있는 설명 문장은 다음과 같습니다.

"기존 ONVIF 카메라는 그대로 연결하고, 녹화와 검색을 맡는 NVR만 새 장비로 바꾸는 방식입니다. 표준 ONVIF·RTSP 호환은 Standard 에디션에 포함되어 있어 카메라 연결을 위해 상위 에디션이 필요하지 않습니다."
"라이선스는 장비 단위로 발급되며, 채널당 추가 라이선스 과금이 없습니다. 채널을 늘려도 채널마다 비용이 붙는 구조가 아닙니다."
"IP 검색은 검색 중에 카메라 계정을 시도하지 않고, 등록할 때 입력한 계정만 사용합니다. 검색 결과의 스트림 주소에도 계정은 가려진 채로 표시됩니다."

RTSP 주소에 계정을 직접 넣는 카메라라면 한 가지를 더 설명할 수 있습니다. 주소에 사용자:비밀번호@ 형태로 계정을 넣고 계정 칸을 비워 두면, 저장할 때 계정이 카메라 설정으로 옮겨지고 비밀번호는 암호화됩니다. 저장된 URL과 스트림 주소에는 계정이 남지 않습니다.

위 설명과 함께 169.254 주소처럼 카메라 네트워크 설정이 필요할 수 있는 경우를 미리 말해 두면, 제안의 신뢰도가 올라갑니다. 설치업체가 "될 수도 있고 안 될 수도 있다"고 말하는 대신 "이 조건이면 되고, 이런 경우에는 카메라 설정을 한 번 바꿔야 한다"고 말할 수 있어야 발주처가 판단하기 쉽습니다.

정리: 교체 제안 전에 확인할 다섯 가지

교체 제안은 결국 다섯 가지를 확인하는 일입니다.

  1. ONVIF 카메라와 RTSP 전용 카메라를 나눕니다.
  2. 같은 서브넷은 자동 검색으로, 그 밖의 대역은 IP 검색으로 찾습니다. IP 검색은 한 번에 /24까지만 훑습니다.
  3. 등록할 때 계정은 둘 다 입력하거나 둘 다 비우고, 모든 채널 및 스트림 자동 추가를 켭니다.
  4. 상태 배지가 온라인인지, 채널과 스트림이 생겼는지 확인합니다.
  5. 169.254 주소가 나오면 카메라 네트워크 설정을 먼저 바꿉니다.

확인 결과는 현장 메모로 남겨 두세요. 검색 결과 화면과 등록 뒤 카메라 목록을 캡처해 두면 발주처에 제안 근거를 보여 줄 때도, 등록 이후 연결 문제가 생겼을 때 원인을 따라갈 때도 도움이 됩니다.

기존 카메라를 살리는 NVR 교체 제안을 준비하고 계신다면, 현장 카메라 기종과 대수, 검색할 대역을 미리 정리해 두시고 설치 파트너 상담 신청을 해 주십시오.

Many buildings already have ONVIF cameras installed, and clients sometimes ask to keep the cameras and replace only the NVR. This is the NVR replacement proposal. Installers welcome the request, but writing the proposal raises questions: can only the NVR be replaced without buying new cameras, how do you find cameras on another subnet, and will the registration process stretch the site visit? This post lays out, in the order you would work on site, how to replace the NVR while keeping the existing cameras.

First, check whether the existing cameras can be reused

Before you make the proposal, sort the site cameras into two groups. That makes the work easier to schedule. NOX registers cameras that support ONVIF Profile S and T through discovery. Cameras without ONVIF support are registered by entering the RTSP address directly. In the manual add screen, the name and RTSP address are required; the username and password are optional.

Camera typeHow to registerChannels and streams
ONVIF camera (Profile S and T)ONVIF discovery, then registerChannels and streams are pulled in by discovery
Camera without ONVIF supportEnter the RTSP address manuallyAdd channels and streams by hand

When you add an RTSP camera, a "Main" channel and a "main" stream are created with it. In the manual add screen, the RTSP address must start with a lowercase rtsp://. An address written as RTSP:// in uppercase is saved, but no video appears. If the address needs a space, encode it as %20.

Step 1: Find cameras on the same subnet with auto discovery

Before the site visit, list the camera models and count, each camera's IP address or range, and the administrator account. Having this ready means you will have fewer things to re-check on site. In particular, confirm that the network interface the cameras are connected to is attached to NOX.

Start ONVIF discovery from the ONVIF Discovery tab on the add camera screen. The default method is Auto Discovery. NOX uses multicast WS-Discovery on its physical network interfaces to find cameras on the same subnet. Virtual interfaces used only inside NOX (such as container bridges) and interfaces that are disconnected are skipped, and no discovery request is sent on them. Auto discovery has no input fields, so confirm the method and press Start Discovery.

When discovery finishes, the result is one of three things.

  • Cameras found: a results table appears.
  • Completed with 0 cameras: the message "No cameras found" appears.
  • Discovery itself failed: a red error and the reason for the failure appear.

"0 cameras" and "discovery failed" are shown differently, so you can tell the causes apart. With 0 cameras, the cameras may be on another subnet or behind a switch that blocks multicast. In that case, use IP discovery, the next step. To narrow down the cause, check in this order.

  1. Confirm that the cameras are on the same network as NOX. Discovery only reaches cameras on a network interface that is connected to NOX.
  2. Confirm that ONVIF is enabled on the cameras.
  3. Check the firewall settings between NOX and the cameras.
  4. If the result is "No cameras found", discovery worked and there are simply no cameras in that scope. If a red error appeared, discovery itself failed, so start with the reason shown.
  5. If the results show only 169.254.x.x addresses, fix the camera network settings first (see "Common blockers and how to clear them" below).

Step 2: Use IP discovery for cameras beyond a router

IP discovery sends discovery requests directly to the IP addresses you specify. Use it for cameras behind a router, on another subnet, or in an environment where multicast is blocked by switches. There are two discovery types.

  • Range discovery (default): enter a start IP and an end IP.
  • Single discovery: enter one camera IP address.

The Start Discovery button is enabled only when the input is valid. The N targets count appears below the button, so you can see how many addresses will be scanned before you start.

On site, pay particular attention to the size of the target range. One discovery can cover at most 254 targets, which is one /24 subnet. For a wider range, split it by subnet and run several discoveries. For example, 10.0.0.1 ~ 10.0.15.254 should be run as 16 separate ranges: 10.0.0.1 ~ 10.0.0.254, 10.0.1.1 ~ 10.0.1.254, and so on. Scanning too many addresses at once loads the ARP and neighbor tables of network devices, and camera responses can be lost.

IP discovery does not try camera accounts during the scan. It sends only ONVIF discovery requests to the specified IPs and reads the name, manufacturer, and model that each responding camera reports about itself. The username and password are used only with the values you enter in the registration step, after the scan finishes.

IP discovery does not trust responses blindly. Responses from addresses outside the target range are ignored, so a device you did not specify cannot appear in the results. If the host in the access address the camera reports differs from the address that actually responded, NOX uses the address that actually responded.

IP discovery is recorded in the audit log as a Discovery action. The discovery method, target count, number of cameras found, and a summary of the scanned range are recorded, so you can trace who scanned which range and when. A discovery that is cancelled or fails after it starts is still recorded. Requests that end before the scan starts, such as an input format error or a target count over the limit, are not recorded.

Only one IP discovery runs at a time across the whole server. If another discovery is in progress in another window, the error "Another discovery is in progress" appears. Wait a moment and try again.

Step 3: Register cameras and pull in channels and streams in one pass

The discovery results table has these columns: select, name, IP address, manufacturer, model, username, and password. Name, manufacturer, and model are what the camera reports about itself. The username and password cells are for you to fill in. Check the cameras you want to register and enter the account for each camera. Fill in both cells or leave both empty. If any camera has only one of them filled in, registration does not start, and a warning appears with that camera's name.

The Add all channels and streams automatically option is on by default. With it on, NOX searches for and adds channels and streams after the camera is registered. With it off, only the camera is registered, and you must add channels and streams later by hand.

A camera that is already registered (same IP:port) gets a yellow Duplicate badge and cannot be selected. This prevents registering the same camera twice. If you restart the discovery, the previous results, selections, and any credentials you entered are all cleared, so it is safer to finish all discovery first and enter accounts afterward.

After registration, check the status badges in the camera list. Online is green, offline is red, and error is gray. The badges update in real time based on connection checks that run about every 10 seconds. A newly registered camera changes to online within the first check cycle, without a page refresh. Even if a badge shows online, confirm that channels and streams were actually created. Expand the camera node in the resource tree to see its channels, and expand a channel node to see its streams. It is a good idea to confirm that video appears in the live view before you leave the site.

If you have dozens of cameras, use the Import Cameras button on the camera list page to register many at once. Drag and drop or select a YAML file (.yaml or .yml) or an exported camera file (.noxcam). The camera list appears as a table, and only the checked cameras are registered. You can download the YAML template with the Download Template button. Each row gets a Valid, Invalid, or Duplicate badge, and invalid or duplicate cameras cannot be selected. Duplicates are judged by IP, port, and RTSP URL; the account and password inside the URL are excluded from the comparison. The same address with a different account counts as a duplicate. An encrypted .noxcam file does not contain passwords. A camera that had a password set shows a Re-enter password badge and a warning, so you must enter the password again after import.

Discovering channels and streams manually

Use manual discovery if automatic addition was turned off or the camera's profile has changed.

  • Channel discovery: hover over an ONVIF camera in the resource tree and press the Discover icon that appears, or choose Discover Channels from the right-click menu. Press Start Channel Discovery to get a channel list showing name, resolution, and FPS. Select the channels you need and press Create Selected Channels.
  • Stream discovery: on an ONVIF channel, choose Discover Streams the same way. Each profile shows its main or sub type, resolution, FPS, bitrate, and codec, and the default transport is TCP. Selected streams are created one at a time, and if some fail, the rest are still attempted.

The addresses in stream discovery results are display-only, with the username and password masked. When a stream is created, the device fetches the address from the camera again and stores it, so camera passwords are neither shown nor sent in the discovery results. The camera must respond when the stream is created. If you see an error saying stream information could not be retrieved, check the camera connection and try again. If you see "The selected stream could not be found on the camera", the camera profile has changed, so run stream discovery again and add the stream.

Common blockers and how to clear them

  • A camera found at 169.254.x.x: the camera did not get a DHCP lease and has assigned itself a link-local address. NOX does not register this address. Use the camera vendor's tool or the camera's web page to set a fixed IP on the device's network range, or switch the camera to DHCP, then discover again. You may need to change a camera setting once, so tell the client about this at the proposal stage.
  • Addresses that cannot be registered: loopback addresses (127.0.0.1, localhost), 0.0.0.0, and multicast addresses cannot be registered. An address made of the NOX device's own address plus the media server port is also blocked. In these cases, the message "This address cannot be used" appears.
  • Discovery range includes addresses that cannot be scanned: if the range includes 0.0.0.0, multicast (224.0.0.0/4), or reserved space (240.0.0.0/4), the scan does not start, and the blocked range is shown. Split the range and enter it again.
  • Stream address format errors: an RTSP address must start with a lowercase rtsp:// or rtsps://, and it cannot contain spaces or control characters. Addresses starting with http://, or values that contain only a path without a host, are not accepted.
  • Video stopped after a camera's IP changed: do not delete the camera and register it again. Deleting it permanently erases its recordings. Instead, edit the camera, change the IP address to the device's new address, and confirm the address change. If camera IPs change often on site, set a fixed IP on the camera or reserve the address on the DHCP server.

How to explain it to the client

Retail, industrial, and building operators on the client side want to know what keeping the existing cameras means on site. Here are sentences installers can reuse as they are.

"The existing ONVIF cameras stay connected as they are, and only the NVR that handles recording and search is replaced with new equipment. Standard ONVIF and RTSP compatibility is included in the Standard edition, so no higher edition is needed to connect the cameras."
"Licenses are issued per device, and there is no additional license fee per channel. Adding channels does not add a cost for each one."
"IP discovery does not try camera accounts during the scan. It uses only the accounts you enter when registering cameras. Stream addresses in the results also show the account masked."

If a camera takes its account directly in the RTSP address, you can explain one more point. When the account is written in the form username:password@ and the account fields are left empty, the account is moved into the camera settings on save, and the password is encrypted. The account does not remain in the saved URL or the stream address.

Mention in advance any cases where camera network settings may be needed, such as a 169.254 address. That raises the credibility of the proposal. Rather than saying "it may or may not work," the installer should be able to say "it works under these conditions, and in these cases one camera setting has to be changed." That makes the decision easier for the client.

Summary: five checks before you make the replacement proposal

A replacement proposal comes down to checking five things.

  1. Separate ONVIF cameras from RTSP-only cameras.
  2. Find cameras on the same subnet with auto discovery, and everything else with IP discovery. IP discovery covers at most one /24 per run.
  3. When registering, fill in both account fields or leave both empty, and keep Add all channels and streams automatically on.
  4. Confirm that the status badges show online and that channels and streams were created.
  5. If a 169.254 address appears, change the camera network settings first.

Keep your findings as on-site notes. Capturing the discovery results screen and the camera list after registration helps both when you show the client the basis for your proposal and when you trace the cause of a connection problem after registration.
