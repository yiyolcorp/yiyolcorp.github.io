건물에 ONVIF 카메라가 이미 설치되어 있는데, 고객이 "카메라는 그대로 두고 NVR만 바꿔 달라"고 요청하는 경우가 있습니다. 이른바 NVR 교체 제안입니다. 설치업체 입장에서는 반가운 요청이지만, 제안서를 쓰려고 하면 막히는 지점이 생깁니다. 카메라를 새로 들이지 않고 NVR만 교체할 수 있는지, 다른 대역에 있는 카메라는 어떻게 찾는지, 등록 과정이 복잡해 현장 시간이 늘어나지 않는지가 그렇습니다. 이 글에서는 기존 카메라를 살려 NVR을 교체하는 절차를 현장 순서대로 정리합니다.

기존 카메라가 교체 대상이 되는지 먼저 확인하세요

제안 전에 현장 카메라를 두 종류로 나눠 두면 작업 시간을 잡기 쉽습니다. NOX는 ONVIF Profile S·T를 지원하는 카메라를 검색으로 등록합니다. ONVIF를 지원하지 않는 카메라는 RTSP 주소를 직접 입력해 등록합니다. 수동 추가 화면에서 이름과 RTSP 주소는 필수이고, 사용자명과 비밀번호는 선택입니다.

카메라 종류등록 방법채널·스트림
ONVIF 카메라 (Profile S·T)ONVIF 검색 후 등록검색으로 채널과 스트림을 가져옴
ONVIF 미지원 카메라RTSP 주소를 직접 입력해 수동 추가채널과 스트림을 수동으로 추가

RTSP 카메라를 추가하면 "Main" 채널과 "main" 스트림이 카메라와 함께 만들어집니다. 카메라 수동 추가 화면의 RTSP 주소는 소문자 rtsp://로 시작해야 합니다. 대문자로 쓴 RTSP:// 주소는 저장은 되지만 영상이 나오지 않습니다. 주소에 공백이 필요하면 %20으로 인코딩해 입력합니다.

1단계: 자동 검색으로 같은 대역의 카메라를 찾습니다

현장에 가기 전에 카메라 기종과 대수, 각 카메라의 IP 주소 또는 대역, 관리자 계정을 먼저 정리해 두면 현장에서 다시 확인할 일이 줄어듭니다. 특히 카메라가 연결된 네트워크 인터페이스가 NOX에 물려 있는지 확인하세요.

ONVIF 카메라 검색은 카메라 추가 화면의 ONVIF 검색 탭에서 시작합니다. 기본 검색 방식은 자동 검색입니다. NOX의 물리 네트워크 인터페이스에서 멀티캐스트 WS-Discovery로 같은 서브넷의 카메라를 찾습니다. NOX 내부 전용 가상 인터페이스(컨테이너 브리지 등)와 연결이 끊긴 인터페이스에는 검색 요청을 보내지 않고 건너뜁니다. 자동 검색은 입력 칸이 없어서 검색 방식을 확인하고 검색 시작만 누르면 됩니다.

검색이 끝나면 결과는 세 가지 중 하나로 표시됩니다.

  • 카메라를 찾은 경우: 검색 결과 테이블이 나타납니다.
  • 성공했지만 0대인 경우: "발견된 카메라가 없습니다" 안내가 나타납니다.
  • 검색 자체가 실패한 경우: 붉은색 오류와 실패 사유가 나타납니다.

"0대"와 "검색 실패"는 다르게 표시되므로 원인을 나눠 볼 수 있습니다. 0대라면 카메라가 다른 서브넷에 있거나 멀티캐스트가 막힌 스위치 뒤에 있을 수 있습니다. 이때는 다음 단계인 IP 검색을 씁니다. 원인을 좁히려면 아래 순서로 점검합니다.

  1. 카메라가 NOX와 같은 네트워크에 있는지 확인합니다. 카메라가 붙은 네트워크 인터페이스가 NOX에 연결되어 있어야 자동 검색이 닿습니다.
  2. 카메라의 ONVIF 기능이 켜져 있는지 확인합니다.
  3. NOX와 카메라 사이의 방화벽 설정을 확인합니다.
  4. 결과가 "발견된 카메라가 없습니다"이면 검색은 정상이고 그 대상에 카메라가 없는 것입니다. 붉은색 오류 알림이 나왔다면 검색 자체가 실패한 것이므로 표시된 사유부터 봅니다.
  5. 검색 결과에 169.254.x.x 주소만 보인다면 카메라 네트워크 설정부터 고칩니다(아래 "현장에서 자주 막히는 지점은 이렇게 풉니다" 참고).

2단계: 라우터 너머 카메라는 IP 검색으로 찾습니다

IP 검색은 지정한 IP 주소로 검색 요청을 직접 보냅니다. 라우터 너머나 다른 서브넷에 있는 카메라, 멀티캐스트가 차단된 스위치 환경에서 씁니다. 검색 유형은 두 가지입니다.

  • 범위 검색(기본): 시작 IP와 끝 IP를 입력합니다.
  • 단일 검색: 카메라 IP 주소 하나를 입력합니다.

입력이 유효해야 검색 시작 버튼이 켜집니다. 버튼 아래에 대상 N개가 표시되므로 검색 전에 몇 개의 주소를 훑는지 확인할 수 있습니다.

현장에서 특히 신경 쓸 부분은 검색 대상의 크기입니다. 한 번에 검색할 수 있는 대상은 최대 254개, 즉 /24 서브넷 하나 분량입니다. 더 넓은 대역은 서브넷 단위로 나눠 여러 번 검색합니다. 예를 들어 10.0.0.1 ~ 10.0.15.254는 10.0.0.1 ~ 10.0.0.254, 10.0.1.1 ~ 10.0.1.254처럼 16번으로 나눠 검색합니다. 한 번에 너무 많은 주소를 훑으면 네트워크 장비의 ARP·이웃 테이블에 부담이 생겨 카메라의 응답이 유실될 수 있습니다.

IP 검색은 검색 과정에서 카메라 계정을 시도하지 않습니다. 지정한 IP에 ONVIF 검색 요청만 보내고, 응답한 카메라가 스스로 알리는 이름·제조사·모델 정보를 읽습니다. 사용자명과 비밀번호는 검색이 끝난 뒤 등록 단계에서 입력한 값만 사용됩니다.

IP 검색은 응답을 그대로 믿지 않습니다. 검색 대상 밖의 주소에서 온 응답은 무시되므로, 지정하지 않은 장치가 결과에 끼어들 수 없습니다. 카메라가 알려 준 접속 주소의 호스트가 실제 응답 주소와 다르면 실제로 응답이 온 주소를 씁니다.

IP 검색은 감사 로그에 검색 액션으로 남습니다. 검색 방식, 대상 수, 발견 대수와 함께 검색한 범위의 요약이 기록되므로 누가 언제 어떤 대역을 검색했는지 추적할 수 있습니다. 검색을 시작한 뒤 취소하거나 실패해도 기록이 남고, 입력 형식 오류나 대상 수 초과처럼 스캔이 시작되기 전에 끝난 요청은 기록되지 않습니다.

IP 검색은 서버 전체에서 한 번에 한 건만 실행됩니다. 다른 창에서 검색이 진행 중이면 "다른 검색이 진행 중입니다" 오류가 표시되므로 잠시 후 다시 시도합니다.

3단계: 등록하면서 채널과 스트림을 함께 가져옵니다

검색 결과 테이블에는 선택, 이름, IP 주소, 제조사, 모델, 사용자명, 비밀번호 열이 있습니다. 이름과 제조사·모델은 카메라가 스스로 알린 정보이고, 사용자명과 비밀번호 칸은 직접 입력하는 칸입니다. 등록할 카메라를 체크하고 카메라마다 계정을 입력합니다. 두 칸은 둘 다 입력하거나 둘 다 비워 두어야 합니다. 한쪽만 입력된 카메라가 있으면 등록이 시작되지 않고, 해당 카메라 이름과 함께 경고가 표시됩니다.

등록 화면의 모든 채널 및 스트림 자동 추가 옵션은 기본으로 켜져 있습니다. 이 옵션을 켜 두면 카메라를 등록한 뒤 채널과 스트림을 자동으로 검색해 추가합니다. 끄면 카메라만 등록되고 채널과 스트림은 나중에 직접 추가해야 합니다.

이미 등록된 카메라(같은 IP:포트)에는 노란색 중복 배지가 붙고 선택할 수 없습니다. 같은 카메라를 두 번 등록하는 실수를 막아 줍니다. 검색을 다시 시작하면 이전 결과와 선택, 입력해 둔 자격증명이 모두 지워지므로, 검색을 모두 끝낸 뒤에 계정을 입력하는 것이 안전합니다.

등록이 끝나면 카메라 목록의 상태 배지를 확인합니다. 온라인은 초록색, 오프라인은 빨간색, 오류는 회색으로 표시되며 약 10초 주기의 연결 점검 결과에 따라 실시간으로 바뀝니다. 새로 등록한 카메라는 새로고침 없이 첫 점검 주기 안에 온라인으로 바뀝니다. 배지가 온라인이라도 채널과 스트림이 실제로 생겼는지 확인하세요. 리소스 트리에서 카메라 노드를 펼치면 채널 목록이, 채널 노드를 펼치면 스트림 목록이 나타납니다. 라이브 화면에 영상이 나오는지까지 본 뒤 현장을 떠나는 것이 좋습니다.

카메라가 수십 대라면 카메라 목록 페이지의 카메라 가져오기 버튼으로 여러 대를 한 번에 등록할 수 있습니다. YAML 파일(.yaml·.yml)이나 카메라 내보내기 파일(.noxcam)을 끌어다 놓거나 선택하면 카메라 목록이 표로 나오고, 체크한 카메라만 등록됩니다. 템플릿 다운로드 버튼으로 YAML 양식을 받을 수 있습니다. 각 행에는 Valid, Invalid, Duplicate 배지가 붙으며, 유효하지 않거나 중복된 카메라는 선택할 수 없습니다. 중복은 IP·포트·RTSP URL로 판정하며, URL에 든 계정과 비밀번호는 비교에서 뺍니다. 계정만 다른 같은 주소는 중복입니다. 암호화된 .noxcam 파일에는 비밀번호가 들어 있지 않습니다. 비밀번호가 설정돼 있던 카메라는 비밀번호 재입력 필요 배지와 경고가 표시되므로, 가져온 뒤 다시 입력해야 합니다.

채널과 스트림을 직접 검색하는 방법

자동 추가를 껐거나 카메라의 설정(프로파일)이 바뀐 경우에는 직접 검색합니다.

  • 채널 검색: 리소스 트리에서 ONVIF 카메라에 마우스를 올리면 나타나는 검색 아이콘을 누르거나, 우클릭 메뉴에서 채널 검색을 고릅니다. 채널 검색 시작을 누르면 이름·해상도·FPS가 표시된 채널 목록이 나옵니다. 필요한 채널을 고르고 선택한 채널 생성을 누릅니다.
  • 스트림 검색: ONVIF 채널에서도 같은 방식으로 스트림 검색을 고릅니다. 프로파일마다 main·sub 타입, 해상도, FPS, 비트레이트, 코덱이 표시되며 Transport 기본값은 TCP입니다. 선택한 스트림은 하나씩 차례로 만들어지고, 일부가 실패해도 나머지는 계속 시도합니다.

스트림 검색 결과의 주소는 사용자명과 비밀번호를 가린 표시용입니다. 스트림을 만들 때 장비가 카메라에서 주소를 다시 받아 저장하므로, 검색 결과에는 카메라 비밀번호가 표시되거나 전송되지 않습니다. 대신 스트림을 만들 때는 카메라가 응답해야 합니다. 스트림 정보를 가져오지 못했다는 오류가 나오면 카메라 연결 상태를 확인한 뒤 다시 시도합니다. "카메라에서 선택한 스트림을 찾을 수 없습니다" 오류가 나오면 카메라 프로파일이 바뀐 것이므로 스트림 검색을 다시 해서 추가합니다.

현장에서 자주 막히는 지점은 이렇게 풉니다

  • 169.254.x.x 주소로 검색되는 카메라: 카메라가 DHCP를 받지 못해 스스로 정한 링크 로컬 주소입니다. NOX는 이 주소를 등록하지 않습니다. 카메라 제조사 도구나 카메라 웹 화면에서 장비 네트워크 대역의 고정 IP를 지정하거나 DHCP를 사용하도록 바꾼 뒤 다시 검색합니다. 카메라 쪽 설정을 한 번은 건드려야 할 수 있으므로, 제안 단계에서 미리 알려 두는 것이 좋습니다.
  • 등록할 수 없는 주소: 루프백(127.0.0.1, localhost), 0.0.0.0, 멀티캐스트 주소는 등록되지 않습니다. NOX 장비 자신의 주소에 media server 포트를 붙인 주소도 막힙니다. 이때는 "사용할 수 없는 주소입니다" 메시지가 표시됩니다.
  • 검색 대역에 검색할 수 없는 주소가 섞인 경우: 범위에 0.0.0.0, 멀티캐스트(224.0.0.0/4), 예약 대역(240.0.0.0/4)이 포함되면 검색 시작이 막히고 걸린 대역이 표시됩니다. 범위를 나눠 다시 입력합니다.
  • 스트림 주소 형식 오류: RTSP 주소는 소문자 rtsp:// 또는 rtsps://로 시작해야 하고, 공백과 제어 문자는 넣을 수 없습니다. http://로 시작하는 주소나 호스트 없이 경로만 쓴 값은 받지 않습니다.
  • 카메라 IP가 바뀐 뒤 영상이 끊긴 경우: 카메라를 삭제하고 다시 등록하지 마십시오. 삭제하면 녹화 영상이 영구 삭제됩니다. 카메라 편집에서 IP 주소를 장치의 새 주소로 바꾸고 주소 변경을 확인합니다. 카메라 IP가 자주 바뀌는 현장이라면 카메라에 고정 IP를 지정하거나 DHCP 서버에서 주소를 예약해 두는 것이 좋습니다.

발주처에게는 이렇게 설명하면 됩니다

발주처의 리테일·산업·빌딩 운영자는 기존 카메라를 살리는 방식이 현장에 무엇을 뜻하는지 궁금해합니다. 설치업체가 그대로 옮겨 쓸 수 있는 설명 문장은 다음과 같습니다.

"기존 ONVIF 카메라는 그대로 연결하고, 녹화와 검색을 맡는 NVR만 새 장비로 바꾸는 방식입니다. 표준 ONVIF·RTSP 호환은 Standard 에디션에 포함되어 있어 카메라 연결을 위해 상위 에디션이 필요하지 않습니다."

"라이선스는 장비 단위로 발급되며, 채널당 추가 라이선스 과금이 없습니다. 채널을 늘려도 채널마다 비용이 붙는 구조가 아닙니다."

"IP 검색은 검색 중에 카메라 계정을 시도하지 않고, 등록할 때 입력한 계정만 사용합니다. 검색 결과의 스트림 주소에도 계정은 가려진 채로 표시됩니다."

RTSP 주소에 계정을 직접 넣는 카메라라면 한 가지를 더 설명할 수 있습니다. 주소에 사용자:비밀번호@ 형태로 계정을 넣고 계정 칸을 비워 두면, 저장할 때 계정이 카메라 설정으로 옮겨지고 비밀번호는 암호화됩니다. 저장된 URL과 스트림 주소에는 계정이 남지 않습니다.

위 설명과 함께 169.254 주소처럼 카메라 네트워크 설정이 필요할 수 있는 경우를 미리 말해 두면, 제안의 신뢰도가 올라갑니다. 설치업체가 "될 수도 있고 안 될 수도 있다"고 말하는 대신 "이 조건이면 되고, 이런 경우에는 카메라 설정을 한 번 바꿔야 한다"고 말할 수 있어야 발주처가 판단하기 쉽습니다.

정리: 교체 제안 전에 확인할 다섯 가지

교체 제안은 결국 다섯 가지를 확인하는 일입니다.

  1. ONVIF 카메라와 RTSP 전용 카메라를 나눕니다.
  2. 같은 서브넷은 자동 검색으로, 그 밖의 대역은 IP 검색으로 찾습니다. IP 검색은 한 번에 /24까지만 훑습니다.
  3. 등록할 때 계정은 둘 다 입력하거나 둘 다 비우고, 모든 채널 및 스트림 자동 추가를 켭니다.
  4. 상태 배지가 온라인인지, 채널과 스트림이 생겼는지 확인합니다.
  5. 169.254 주소가 나오면 카메라 네트워크 설정을 먼저 바꿉니다.

확인 결과는 현장 메모로 남겨 두세요. 검색 결과 화면과 등록 뒤 카메라 목록을 캡처해 두면 발주처에 제안 근거를 보여 줄 때도, 등록 이후 연결 문제가 생겼을 때 원인을 따라갈 때도 도움이 됩니다.

기존 카메라를 살리는 NVR 교체 제안을 준비하고 계신다면, 현장 카메라 기종과 대수, 검색할 대역을 미리 정리해 두시고 설치 파트너 상담 신청을 해 주십시오.

관련 글

  • 중국산 IP카메라, 인터넷 차단으로 격리하고 NOX를 이용해서 안전하게 쓰는 법 — 기존 카메라를 교체하지 않고 NOX 앞단에 두는 방법
  • NVR 디스크 용량 계산기 (시스템 + 데이터) — 채널 수와 보관 기간으로 교체 규모 잡기

Sometimes a building already has ONVIF cameras installed, and the customer asks to keep the cameras and replace only the NVR. Installers welcome this request, but once they start writing the proposal, a few questions get stuck: can the cameras really stay and only the NVR be swapped, how do you find cameras on other subnets, and will registration eat up site time? This post lays out the steps for replacing the NVR while keeping the existing cameras, in the order you would follow on site.

Check Whether the Existing Cameras Can Stay First

Before the proposal, split the cameras on site into two groups so the work is easier to estimate. NOX registers cameras that support ONVIF Profile S and T through discovery. Cameras that do not support ONVIF are registered by entering their RTSP address directly. On the manual add screen, the name and RTSP address are required, while the username and password are optional.

Camera typeHow to registerChannels and streams
ONVIF camera (Profile S·T)Register after ONVIF discoveryChannels and streams are pulled in during discovery
Non-ONVIF cameraAdd manually by entering the RTSP addressChannels and streams are added manually

When you add an RTSP camera, a "Main" channel and a "main" stream are created along with the camera. The RTSP address on the manual camera add screen must start with a lowercase rtsp://. An address written in uppercase as RTSP:// is saved, but no video appears. If the address needs a space, encode it as %20.

Step 1: Find Cameras on the Same Subnet with Auto Discovery

Before going on site, prepare the camera models and count, each camera's IP address or range, and the administrator account. Having these ready reduces the number of checks you need on site. In particular, confirm that the network interface the cameras are attached to is connected to NOX.

Camera discovery starts on the ONVIF Discovery tab of the add camera screen. The default method is Auto Discovery. NOX sends multicast WS-Discovery from its physical network interfaces to find cameras on the same subnet. Virtual interfaces used only inside NOX, such as container bridges, and interfaces that are disconnected are skipped, and no discovery request is sent through them. Auto Discovery has no input fields, so you only need to check the discovery method and click Start Discovery.

When discovery finishes, the result is one of three states:

  • Cameras found: a results table appears.
  • Completed with 0 cameras: the message "No cameras found" appears.
  • Discovery itself failed: a red error and the reason for the failure appear.

A 0-camera result and a failed discovery are shown differently, so you can tell the causes apart. If the result is 0 cameras, the cameras may be on another subnet or behind a switch that blocks multicast. In that case, use IP Search, the next step. To narrow down the cause, check in this order:

  1. Confirm that the cameras are on the same network as NOX. The network interface the cameras are attached to must be connected to NOX for Auto Discovery to reach them.
  2. Confirm that ONVIF is enabled on the cameras.
  3. Check the firewall settings between NOX and the cameras.
  4. If the result is "No cameras found," discovery worked and no camera exists in that target. If a red error appeared, discovery itself failed, so start with the reason shown.
  5. If the results show only 169.254.x.x addresses, fix the camera network settings first (see "Common Field Problems and How to Fix Them" below).

Step 2: Use IP Search for Cameras Beyond a Router

IP Search sends discovery requests directly to the IP addresses you specify. Use it for cameras behind a router, on a different subnet, or in a switch environment that blocks multicast. There are two search types:

  • Range (default): enter a start IP and an end IP.
  • Single: enter one camera IP address.

The Start Discovery button becomes active only when the input is valid. The N targets count appears below the button, so you can check how many addresses will be scanned before you start.

On site, pay particular attention to the size of the search target. A single search can cover at most 254 targets, which is one /24 subnet. For a wider range, split it into subnets and search several times. For example, 10.0.0.1 ~ 10.0.15.254 should be searched as 16 separate ranges: 10.0.0.1 ~ 10.0.0.254, 10.0.1.1 ~ 10.0.1.254, and so on. Scanning too many addresses at once can overload the ARP and neighbor tables of network devices, and camera responses may be lost.

IP Search does not try camera accounts during the search. It only sends an ONVIF discovery request to the specified IP and reads the name, manufacturer, and model that the responding camera reports about itself. The username and password are used only from the values you enter at the registration step after the search.

IP Search does not trust responses blindly. Responses from addresses outside the search target are ignored, so devices you did not specify cannot slip into the results. If the host in the access address reported by the camera differs from the address that actually responded, the address that actually responded is used.

IP Search is recorded in the audit log as a Search action. The discovery method, target count, number of cameras found, and a summary of the searched range are recorded, so you can trace who searched which range and when. A search that is canceled or fails after it starts is still logged. Requests that end before the scan starts, such as input format errors or exceeding the target limit, are not logged.

IP Search runs only one job at a time across the whole server. If another search is in progress in another window, the error "Another discovery is in progress. Please try again shortly" appears, so try again after a moment.

Step 3: Register Cameras and Pull in Channels and Streams Together

The results table has the columns Select, Name, IP Address, Manufacturer, Model, Username, and Password. Name, manufacturer, and model are the information the camera reports about itself, while the username and password cells are for you to fill in. Check the cameras you want to register and enter the account for each camera. Both fields must be filled in, or both left empty. If only one field is filled in for any camera, registration does not start, and a warning appears with that camera's name.

The Automatically add all channels and streams option on the registration screen is on by default. With this on, after a camera is registered, its channels and streams are discovered and added automatically. If you turn it off, only the camera is registered, and channels and streams must be added manually later.

A camera that is already registered (same IP:port) gets a yellow Duplicate badge and cannot be selected. This prevents registering the same camera twice. If you restart discovery, the previous results, selections, and any credentials you entered are all cleared, so it is safer to enter accounts after finishing all discovery.

When registration is done, check the status badge in the camera list. Online is green, offline is red, and error is gray. The badge updates in real time based on the connection check that runs about every 10 seconds. A newly registered camera changes to online within the first check cycle without a page refresh. Even if the badge shows online, confirm that channels and streams were actually created. Expanding a camera node in the resource tree shows its channel list, and expanding a channel node shows its stream list. It is best to leave the site only after confirming that video appears on the live screen.

If you have dozens of cameras, you can register many at once with the Import Cameras button on the camera list page. Drag and drop or select a YAML file (.yaml, .yml) or a camera export file (.noxcam), and the camera list appears as a table; only the cameras you check are registered. The Download Template button provides the YAML template. Each row gets a Valid, Invalid, or Duplicate badge, and invalid or duplicate cameras cannot be selected. Duplicates are judged by IP, port, and RTSP URL, and the account and password inside the URL are excluded from the comparison. The same address with a different account counts as a duplicate. Encrypted .noxcam files do not contain passwords. A camera that had a password set shows a Password re-entry required badge and a warning, so you must enter the password again after importing.

Searching Channels and Streams Directly

Search directly when automatic addition was turned off or when the camera's configuration (profile) has changed.

  • Discover Channels: hover over an ONVIF camera in the resource tree and click the search icon that appears, or choose Discover Channels from the right-click menu. Start the search to see a list of channels with name, resolution, and FPS. Select the channels you need and click Create Selected Channels.
  • Discover Streams: on an ONVIF channel, choose Discover Streams (Profiles) the same way. For each profile, the main or sub type, resolution, FPS, bitrate, and codec are shown, and the Transport default is TCP. Selected streams are created one at a time, and if some fail, the rest are still attempted.

The address in the stream discovery results is a display version with the username and password masked. When a stream is created, the device fetches the address from the camera and saves it, so the camera password is neither shown nor sent in the discovery results. Creating a stream does require the camera to respond. If you see the error "Could not get stream information from the camera. Check the camera connection and try again," check the camera connection and retry. If you see "The selected stream was not found on the camera. Search for streams again, then add it," the camera profile has changed, so run stream discovery again and add the stream.

Common Field Problems and How to Fix Them

  • Cameras found at 169.254.x.x addresses: The camera did not get a DHCP lease and is using a link-local address it chose for itself. NOX does not register this address. Use the camera manufacturer's tool or the camera's web page to set a fixed IP in the device's network range or switch to DHCP, then search again. You may need to change a camera setting once, so tell the customer about this at the proposal stage.
  • Addresses that cannot be registered: Loopback (127.0.0.1, localhost), 0.0.0.0, and multicast addresses cannot be registered. An address that combines NOX's own address with the media server port is also blocked. In that case, the message "This address cannot be used" appears.
  • A search range that includes addresses that cannot be searched: If the range includes 0.0.0.0, multicast (224.0.0.0/4), or reserved space (240.0.0.0/4), the search does not start and the affected range is shown. Split the range and enter it again.
  • Stream address format errors: RTSP addresses must start with lowercase rtsp:// or rtsps://, and spaces and control characters are not allowed. Values starting with http://, or containing only a path without a host, are rejected.
  • Video stops after the camera IP changes: Do not delete the camera and register it again. Deleting it permanently erases its recordings. Instead, edit the camera, change the IP address to the device's new address, and confirm the address change. If camera IPs change often on site, assign a fixed IP to the camera or reserve the address on the DHCP server.

How to Explain It to the Customer

Retail, industrial, and building operators on the customer side want to know what keeping the existing cameras means on site. You can use these sentences as they are:

"Your existing ONVIF cameras stay connected as they are, and only the NVR that handles recording and search is replaced with new equipment. Standard ONVIF and RTSP compatibility is included in the Standard edition, so no higher edition is needed to connect the cameras."

"Licenses are issued per device, and there is no additional license charge per channel. Adding channels does not add a cost for each channel."

"IP Search does not try camera accounts during the search and uses only the accounts entered at registration. Account details stay hidden even in the stream addresses shown in the search results."

If the camera takes its account inside the RTSP address, you can explain one more point. When you put the account in the address in the form username:password@ and leave the account fields empty, the account moves into the camera settings when saved, and the password is encrypted. The saved URL and stream address do not retain the account.

Mentioning cases where camera network settings may be needed, such as 169.254 addresses, in advance alongside the explanation above raises the credibility of the proposal. Installers should be able to say "this works under these conditions, and in these cases the camera settings need to be changed once," rather than "it might work or might not," so the customer can judge more easily.

Summary: Five Things to Check Before Proposing a Replacement

A replacement proposal comes down to checking five things.

  1. Separate ONVIF cameras from RTSP-only cameras.
  2. Use Auto Discovery for the same subnet and IP Search for other ranges. IP Search covers at most one /24 at a time.
  3. When registering, fill in both account fields or leave both empty, and turn on Automatically add all channels and streams.
  4. Check that the status badge shows online and that channels and streams were created.
  5. If a 169.254 address appears, change the camera network settings first.

Keep a record of your checks as on-site notes. Capturing the discovery results screen and the camera list after registration helps when you show the basis of the proposal to the customer, and it helps trace the cause if connection problems appear after registration.

If you are preparing an NVR replacement proposal that keeps the existing cameras, list the camera models, counts, and ranges to search in advance, and then request an installation partner consultation.
