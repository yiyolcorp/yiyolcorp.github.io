NOX MCP 유지보수 점검 설치업체

유지보수 계약 현장이 하나둘 늘면 점검은 어느 순간 병목이 됩니다. 현장마다 NVR 화면을 열고, 카메라 목록에서 끊긴 곳이 없는지 보고, 녹화 기록을 날짜별로 훑고, 저장소 상태를 따로 확인해야 합니다. 이 작업 하나하나는 어렵지 않습니다. 문제는 현장 수만큼 같은 절차를 반복해야 하고, 바쁜 주에는 점검이 뒤로 밀린다는 점입니다. 그리고 가장 곤란한 순간은 사고가 난 뒤에야 "그날 녹화가 빠져 있었다"는 사실을 알게 될 때입니다.

NOX에는 이 반복 점검을 말로 묻는 방법이 있습니다. 장비가 읽기 전용 MCP 서버로 동작해서, Claude Code 같은 MCP 클라이언트가 장비에 접속해 "오프라인 카메라 있어?", "지난 7일간 이 카메라 녹화 빠진 구간은?", "디스크 상태는?" 같은 질문에 답을 가져옵니다. 이 글에서는 점검 세 가지를 말로 묻는 방법, 연결 절차, 안전장치, 그리고 반드시 알아야 할 조건과 한계를 순서대로 정리합니다.

먼저 조건부터 밝힙니다. MCP 연동은 Enterprise 에디션 기능입니다. 같은 네트워크에서만 접속할 수 있고, NIS 보안 모드에서는 쓸 수 없으며, Free 모드(라이선스 미등록·만료)에서도 제공되지 않습니다. 이 한계는 뒤에서 다시 자세히 다룹니다.

점검 세 가지를 말로 묻는다

유지보수 점검의 핵심은 결국 세 가지로 모입니다. 카메라가 살아 있는지, 녹화가 빠지지 않았는지, 저장소가 건강한지입니다. NOX MCP는 각각에 대응하는 도구를 제공합니다.

점검 항목이렇게 묻는다(예시)대응 도구
오프라인·녹화 이상 카메라"지금 오프라인이거나 녹화가 안 되는 카메라 있어?"nox_camera_health
녹화 누락 구간"주차장 입구 카메라, 지난 7일 녹화 빠진 구간 알려줘"nox_recording_coverage
디스크·저장소 상태"저장소 용량이랑 디스크 상태 어때?"nox_storage_status

표의 질문 문구는 이해를 돕기 위한 예시입니다. 실제로는 MCP 클라이언트가 질문을 해석해 알맞은 도구를 골라 호출하므로, 정해진 문장을 외울 필요는 없습니다. 아래에서 도구별로 무엇을 확인해 주는지 풀어 보겠습니다.

오프라인 카메라와 녹화 이상: nox_camera_health

카메라 상태 점검 도구는 카메라별 영상 수신 상태와 녹화 상태(비트레이트, 측정 시각)를 점검하고 문제가 있는 카메라를 표시합니다. 표시되는 문제는 다음과 같습니다.

  • 카메라가 오프라인인 경우
  • 녹화 오류가 있는 경우
  • 녹화 데이터가 흐르지 않는 경우
  • 라이선스, 채널 비활성, 소스 삭제 등의 이유로 녹화가 중지된 경우

화면에서는 카메라 하나하나를 눌러 보지 않으면 놓치기 쉬운 항목들입니다. 특히 "카메라는 온라인인데 녹화 데이터가 흐르지 않는" 상태는 영상이 정상처럼 보여서 늦게 발견되곤 합니다. 이런 상태까지 한 번의 질문으로 훑어볼 수 있습니다.

카메라 목록과 온라인·오프라인 상태, 녹화 설정 요약이 필요하면 nox_list_cameras도 쓸 수 있습니다. 이 도구는 이름 일부로 카메라를 찾아 주고, 다른 도구에 넘길 카메라 ID도 제공합니다. 그래서 "주차장 카메라"처럼 이름으로 말해도 뒤의 도구가 정확한 카메라를 찾아갑니다.

녹화 누락 구간: nox_recording_coverage

녹화 구간 확인 도구는 카메라 한 대를 기준으로 기간별 녹화율과 누락 구간을 알려 줍니다. 알아 둘 점이 몇 가지 있습니다.

  • 한 번에 카메라 한 대, 기간은 최대 7일입니다.
  • 녹화율은 조회 구간 중 현재 시각까지를 기준으로 계산합니다. 아직 오지 않은 미래 시간은 포함하지 않습니다.
  • 공백에는 조회 구간 앞뒤의 공백도 포함됩니다.
  • 누락 구간 목록에서는 기본적으로 60초 미만의 짧은 공백은 생략합니다.

그래서 이 도구는 "정기 점검 때 전체 카메라의 지난주 녹화율을 확인한다"기보다, nox_camera_health에서 의심 카메라를 추린 뒤 그 카메라의 최근 기록을 확인하는 흐름에 잘 맞습니다. 카메라 상태 점검으로 후보를 좁히고, 녹화 구간 확인으로 실제 빠진 시간대를 짚는 순서입니다.

저장소와 디스크: nox_storage_status, nox_system_health

저장소 상태 도구는 저장소 볼륨 용량과 디스크 S.M.A.R.T. 상태를 조회합니다. 디스크 문제는 증상이 눈에 띄기 전에 징후가 먼저 나타나는 경우가 많아서, 정기 점검 항목에 꼭 넣어 두는 것이 좋습니다.

장비 자체의 상태가 궁금하면 시스템 상태 도구(nox_system_health)가 서비스 상태, CPU·메모리·GPU·온도, 유지보수 상태, 소프트웨어 버전을 알려 줍니다. 유지보수나 업그레이드 중에는 서비스 목록이 비어 있을 수 있어서, 이 도구의 결과는 유지보수 상태와 함께 해석해야 합니다.

점검 세 가지 외에도 이벤트 검색과 통계, 객체 검색, 재생 링크 같은 도구가 있어 모두 10종이 제공됩니다. 점검 중에 이상한 구간을 발견하면 재생 링크 도구가 해당 시각의 재생 화면을 여는 웹 UI 링크를 만들어 줍니다. 영상 자체는 MCP 결과로 돌아오지 않으므로, 링크를 열고 사람이 직접 확인하는 방식입니다.

연결하는 방법

연결은 네 단계입니다. 장비 관리 화면에서 키를 발급하고, MCP 클라이언트에 등록하고, 장비 인증서를 신뢰하게 하고, 연결 상태를 확인합니다. 아래는 Claude Code 기준입니다.

1단계: AI 에이전트 키를 발급합니다

시스템 설정의 API 키 화면에서 키 발급을 누르고 이름, 만료, 허용 IP를 입력합니다. 그다음 중요한 선택이 두 가지 있습니다.

  1. 용도에서 AI 에이전트(MCP) 를 선택합니다. 라이선스에 MCP 기능이 없으면 이 용도가 잠겨 있고 안내 문구가 표시됩니다.
  2. 허용할 도구와 카메라 범위를 고릅니다. 도구는 기본으로 10종이 모두 선택되어 있고 1개 이상 선택해야 발급됩니다. 카메라 범위는 전체 카메라 또는 리소스 그룹 지정 중에서 고릅니다.

점검 전용으로 쓸 키라면 점검에 필요한 도구만 남기는 것을 권합니다. 예를 들어 카메라 상태 점검, 녹화 구간 확인, 저장소 상태, 시스템 상태, 카메라 목록 정도로 줄일 수 있습니다. 도구 선택은 키에 서명되어 들어가므로, 발급 뒤에 바꾸려면 키를 회전해야 합니다.

카메라 범위도 신중히 정합니다. 키의 조회 범위는 발급한 관리자 계정의 권한이 아니라 발급할 때 고른 카메라 범위를 따릅니다. 전체 카메라로 발급하면 그 장비의 모든 카메라 데이터를 조회하므로, 유지보수 대상 범위만 리소스 그룹으로 묶어 지정하는 방식이 안전합니다. 에이전트에 전달되어도 되는 카메라만 범위에 넣으세요.

2단계: MCP 클라이언트에 등록합니다

발급이 끝나면 결과 창에 AI 에이전트 연결 영역이 나타납니다. 접속 주소와 키가 들어간 Claude Code 등록 명령이 복사 버튼과 함께 표시됩니다. 형식은 다음과 같습니다.

claude mcp add --transport http nox-<키 이름> https://<장비 주소>/agent/mcp \
  --header "Authorization: Bearer <AI 에이전트 키>"

몇 가지 주의할 점이 있습니다.

  • 접속 주소 끝에 슬래시를 붙이면 안 됩니다. /agent/mcp/는 연결되지 않습니다.
  • 키는 반드시 Authorization 헤더로 보냅니다. URL 쿼리로는 받지 않습니다.
  • 등록 명령에 키가 그대로 들어 있어서 실행하면 셸 히스토리에 남습니다. 실행 후 해당 줄을 지우세요.
  • 장비 앞 로컬 화면(localhost)에서 발급했다면 명령에 localhost가 들어갑니다. 다른 PC에서 연결할 때는 https://<장비 주소>로 바꿔 쓰세요.
  • Cursor 같은 다른 MCP 클라이언트는 같은 접속 주소와 Authorization 헤더를 그 클라이언트의 원격(HTTP) MCP 서버 설정에 넣습니다.

3단계: 장비 CA 인증서를 신뢰하게 합니다

장비의 HTTPS 인증서는 장비 내부 CA가 서명합니다. 그래서 에이전트를 실행하는 PC가 이 CA를 신뢰해야 접속됩니다.

  1. 결과 창의 장비 CA 인증서 다운로드(ca.crt) 링크를 누르거나, 브라우저에서 https://<장비 주소>/ca.crt를 열어 인증서를 내려받습니다. 로그인은 필요 없습니다.
  2. 에이전트를 실행하는 환경에 NODE_EXTRA_CA_CERTS=<내려받은 파일 경로>를 설정한 뒤 에이전트를 실행합니다.
export NODE_EXTRA_CA_CERTS=$HOME/nox-ca.crt
claude

에이전트가 접속하는 주소(IP 또는 도메인)가 장비 인증서에 들어 있어야 한다는 점도 확인하세요. 들어 있지 않으면 인증서 접속 주소 설정에서 추가해야 합니다.

4단계: 연결을 확인하고 물어봅니다

claude mcp list로 연결 상태를 확인합니다. 연결되어 있다면 이제 "오프라인 카메라 있어?"처럼 물어보면 됩니다. 클라이언트가 해당 도구를 호출하고 결과를 정리해 줍니다.

점검 도구로 써도 안전한 이유

현장 장비에 외부 도구를 붙인다고 하면 가장 먼저 나오는 걱정은 "설정이 바뀌거나 녹화가 멈추면 어떡하나"입니다. NOX MCP는 이 걱정을 구조로 줄여 놓았습니다.

읽기 전용입니다. 장비는 읽기 전용 MCP 서버로 동작하며, 카메라·녹화·설정을 바꾸는 도구가 아예 제공되지 않습니다. 말로 점검하고 조회할 수 있을 뿐, 말로 설정을 고칠 수는 없습니다. 점검에서 문제를 발견하면 고치는 일은 지금처럼 사람이 관리 화면에서 합니다.

도구와 카메라 범위를 키별로 제한합니다. 앞서 본 대로 키마다 허용 도구와 카메라 범위를 정합니다. 현장 담당자 A의 키에는 담당 현장 그룹만, 점검 전용 키에는 점검 도구만 주는 식으로 나눌 수 있습니다. 다만 도구 선택은 MCP 접속에만 적용되며, 같은 키로 REST API를 직접 부르면 읽기 전용 API 권한이 적용됩니다. 카메라 범위는 두 경우 모두 적용됩니다. 그래서 키는 비밀번호처럼 보관하고 만료와 허용 IP를 짧고 좁게 잡는 것이 좋습니다.

민감한 정보는 결과에 담기지 않습니다. 도구 결과에는 카메라 접속 주소와 자격증명, 장치 시리얼 번호, 썸네일 이미지, 사용자 이름이 포함되지 않습니다. 영상 자체도 반환하지 않고, 재생이 필요할 때만 웹 UI 재생 링크를 만들어 줍니다. 링크를 열면 웹 로그인이 필요하고 로그인한 사용자의 권한으로 재생됩니다.

모든 호출이 감사 로그에 남습니다. AI 에이전트 키의 도구 호출은 성공과 실패 모두 1건당 1행으로 감사 로그에 기록됩니다. 어떤 도구를 호출했는지, 결과가 정상이었는지, 어느 PC에서 접속했는지를 사후에 확인할 수 있습니다. 자연어 질의와 번호판 같은 민감 문자열은 원문이 아니라 가려진 형태로 남습니다. 감사 로그 화면에서 카테고리를 AI 에이전트로 고르면 에이전트 호출만 볼 수 있습니다.

호출 상한이 있습니다. 녹화와 라이브 같은 핵심 기능을 보호하려고 MCP 접속에는 키별 호출 상한이 걸려 있습니다. 점검 때문에 장비 본래 기능에 부담이 가는 일을 막기 위한 장치입니다.

오류와 "결과 없음"이 섞이지 않습니다. 권한 판정이 일시적으로 불가능하거나 내부 서비스가 응답하지 않으면 빈 결과가 아니라 오류로 돌려줍니다. 점검에서 이 구분은 중요합니다. "문제없음"으로 보이는 빈 결과가 사실은 조회 실패였다면 점검의 의미가 없기 때문입니다.

알아 둘 조건과 한계

솔직하게 정리합니다. 도입 전에 아래 항목을 꼭 확인하세요.

  • Enterprise 에디션 기능입니다. MCP 기능은 Enterprise 라이선스에 기본 포함됩니다. Free 모드(라이선스 미등록·만료)에서는 제공되지 않습니다. 현장 장비의 라이선스 에디션을 먼저 확인하세요.
  • 같은 네트워크에서만 접속합니다. 에이전트를 실행하는 PC가 장비의 웹 서버에 HTTPS로 접속할 수 있어야 합니다. 클라우드를 거치는 원격 연결은 제공하지 않습니다. 현장 네트워크 안에서 점검하거나, 고객과 합의한 구성으로 장비에 접속할 수 있는 환경이 필요합니다.
  • NIS 보안 모드에서는 쓸 수 없습니다. NIS 보안 모드가 활성인 장비에서는 API 키 기능 전체가 막혀 있고 MCP 접속 주소도 동작하지 않습니다. 또 일반 장비를 NIS 보안 모드로 전환하면 그 전에 발급한 키가 모두 영구 폐기됩니다. 납품 현장이 NIS 보안 모드 대상이라면 이 방법은 쓸 수 없습니다.
  • 조회만 됩니다. 설정 변경, 녹화 시작·중지, 카메라 추가·삭제 같은 작업은 MCP로 할 수 없습니다.
  • MCP 클라이언트는 따로 필요합니다. Claude Code 같은 MCP 클라이언트를 점검 담당자가 준비해야 합니다. 클라이언트의 이용 조건은 해당 서비스 제공사 기준을 따르므로, 이 글에서는 다루지 않습니다.
  • 결과는 사람이 확인합니다. 질문은 말로 하지만, 판단과 조치는 사람이 합니다. 이 글의 질문 문구는 예시이며, 실제 답변의 표현은 사용하는 클라이언트에 따라 달라질 수 있습니다. 의심스러운 구간은 재생 링크로 직접 영상을 확인하세요.
  • 시각을 말할 때는 시간대를 포함합니다. 도구에 시각을 넘길 때는 시간대 오프셋이 필요합니다(예: 2026-10-01T22:00:00+09:00). 클라이언트가 대부분 알아서 처리하지만, 결과가 이상하면 이 부분을 먼저 확인하세요.

이렇게 점검 루틴을 만들어 보세요

도구가 있어도 루틴이 없으면 점검은 여전히 밀립니다. 아래는 하나의 예시입니다.

  1. 현장별로 점검 전용 키를 발급합니다. 도구는 점검에 필요한 것만, 카메라 범위는 해당 현장 그룹으로 정합니다.
  2. 정해진 질문 세 가지를 점검 체크리스트에 넣습니다. 오프라인·녹화 이상 카메라, 의심 카메라의 최근 녹화 누락 구간, 저장소·디스크 상태입니다.
  3. 이상이 보이면 재생 링크로 직접 영상을 확인하고 관리 화면에서 조치합니다.
  4. 점검 결과를 고객 보고에 첨부합니다. 무엇을 확인했는지는 감사 로그에도 남아 있습니다.

점검 질문을 팀 안에서 표준화해 두면 담당자가 바뀌어도 같은 항목을 같은 방식으로 확인할 수 있습니다.

고객에게는 이렇게 설명하세요

유지보수 계약을 제안하거나 갱신할 때 최종 발주처가 궁금해하는 것은 기술 방식이 아니라 "정기 점검을 받고 있다는 근거"입니다. 이렇게 설명할 수 있습니다.

"녹화가 빠진 구간이 없는지, 오프라인 카메라가 없는지, 저장소 상태는 괜찮은지를 정기적으로 확인합니다. 점검은 조회 전용이라 설정이나 녹화에 영향을 주지 않고, 점검 호출은 장비의 감사 로그에 기록으로 남습니다."

점검 도구가 읽기 전용이고 기록이 남는다는 점은 보안 담당자에게도 설명하기 쉬운 부분입니다. 앞서 본 대로 키의 카메라 범위를 해당 현장으로 한정할 수 있으니, 어느 범위까지 점검하는지도 분명하게 말할 수 있습니다.

마치며

유지보수 점검의 목표는 문제를 사고가 되기 전에 찾는 것입니다. NOX MCP는 카메라 상태, 녹화 누락, 저장소 상태라는 세 가지 점검을 말로 묻는 방식으로 바꿔 줍니다. 읽기 전용이고, 키별로 도구와 카메라 범위를 제한하며, 호출 기록이 남기 때문에 현장 장비에 붙이는 점검 도구로 설명하기에 부담이 적습니다. 다만 Enterprise 에디션 기능이고, 같은 네트워크에서만 쓸 수 있고, NIS 보안 모드에서는 쓸 수 없다는 조건은 도입 전에 현장별로 확인해야 합니다.

NOX의 라이선스는 장비 단위이고 채널을 늘린다고 채널당 과금이 붙지 않습니다. 그래서 유지보수 현장의 카메라 수가 늘어도 라이선스 구조 때문에 점검 범위를 줄일 이유는 없습니다. 어떤 에디션이 맞는지, 현장 구성에서 MCP 점검이 가능한지는 상담으로 확인해 드립니다.

MCP 점검을 현장에 적용해 보고 싶으시다면 설치 파트너 상담 신청을 해 주십시오.

MCP 연동은 Enterprise 에디션 기능입니다. 같은 네트워크에서만 접속할 수 있으며 NIS 보안 모드와 Free 모드에서는 제공되지 않습니다. 에디션별 구성과 비용은 상담으로 안내합니다.
