# IP카메라 10대 중 3대, 남의 영상이 열렸다 — 소비자원·KISA 점검으로 만든 CCTV 보안 점검표

2026년 11월 12일, 한국소비자원과 한국인터넷진흥원(KISA)이 시중에 유통되는 IP카메라 10개 제품의 보안 점검 결과를 발표했습니다. 이 중 3개 제품은 사용자 인증 절차가 미흡해, 공격자가 다른 사용자의 카메라 영상과 이미지를 내려받거나 카메라를 원격으로 조작할 수 있는 취약점이 확인됐습니다. 매장, 사무실, 아파트 관리사무소에서 IP카메라를 쓰고 있다면 "우리 카메라는 괜찮은가?"라는 질문이 먼저 떠오를 것입니다.

그런데 이번 점검 결과를 자세히 보면, 사용자가 카메라 하나를 확인하는 것만으로는 답이 나오지 않는 항목이 많습니다. 통신 암호화, 펌웨어 보안 설정, 보안 업데이트 지원 기간은 사는 사람이 바꿀 수 없는 영역이기 때문입니다. 이 글에서는 점검 결과를 정리하고, **카메라 · 네트워크 · 녹화 시스템** 세 단계로 나눈 CCTV 보안 점검표를 제시합니다. 녹화 시스템 단계에서는 NOX NVR/VMS가 어떤 기능으로 이 항목을 받쳐 주는지도 함께 설명합니다.

## 소비자원·KISA 점검에서 무엇이 나왔나요?

점검 대상은 온라인 쇼핑몰 판매 순위와 소비자 설문조사 결과 등을 바탕으로 고른 IP카메라 10개 제품이고, 점검 항목은 기기(하드웨어·네트워크·펌웨어), 모바일 앱, 정책·관리 분야를 합쳐 37개입니다. 보안뉴스 보도(2026-11-12)에 실린 결과는 다음과 같습니다.

| 점검 결과 | 해당 제품 수 |
| --- | --- |
| 사용자 인증 미흡 — 다른 사용자의 영상·이미지 탈취, 카메라 원격 조작 가능 | 3개 |
| 안전한 통신 프로토콜 미사용 | 8개 |
| 비밀번호 정책 미흡 | 5개 |
| 보안 업데이트 지원 기간 미명시 | 6개 |
| 테스트 단자 활성화 | 4개 |
| 펌웨어 보안 설정 보완 필요 | 10개 전부 |

사용자 인증이 미흡했던 3개 제품은 로보뷰 GI-ROBOA7, 브이스타캠 VSTARCAM-800X, 파인뷰 K11입니다. 보도에 따르면 로보뷰와 파인뷰는 개선 계획을 회신하고 개선을 마쳤고, 브이스타캠은 보완 작업을 진행 중입니다. KISA는 제조사에 개선을 권고했고 이행 여부를 계속 점검할 예정이라고 밝혔습니다. 실제 악용 사례가 있었다는 내용은 보도에 없습니다.

눈여겨볼 점은 인증 취약점이 일부 제품의 문제였던 반면, 통신 암호화(8개)와 업데이트 지원 기간(6개), 펌웨어 보안 설정(10개)은 대부분의 제품에 걸친 문제였다는 것입니다. 특정 브랜드를 피하는 것만으로는 충분하지 않다는 뜻입니다.

## 왜 카메라만 바꿔서는 끝나지 않나요?

카메라 보안 문제는 크게 두 갈래입니다. 하나는 사용자가 직접 고칠 수 있는 것(초기 비밀번호, 불필요한 원격 기능, 공유기 포트 개방)이고, 다른 하나는 제조사만 고칠 수 있는 것(인증 구조, 통신 암호화, 펌웨어 설정, 업데이트 지원)입니다. 이번 점검에서 많이 나온 항목은 대부분 두 번째 갈래입니다. 지금 쓰는 카메라가 내일 새로운 취약점으로 보도될 수도 있고, 그때 제조사가 패치를 내지 않으면 사용자가 할 수 있는 일은 많지 않습니다.

같은 주에 나온 두 기사도 같은 방향을 가리킵니다.

- **지원이 끊긴 구형 카메라.** 보안뉴스 「디지털 문단속」(2026-11-14)은 마지막 펌웨어 업데이트가 1년 이상 지났거나 지원 종료(EOL)로 고지된 카메라는 그대로 쓰지 말라고 권하며, 공유기의 포트 포워딩·UPnP 규칙을 직접 지우라고 강조했습니다. 전원만 뽑아서는 공유기의 포트 개방 규칙이 사라지지 않기 때문입니다.
- **중앙서버 하나에 묶인 구조.** 보안뉴스(2026-11-09)는 한 아파트 홈네트워크 운영사의 중앙서버에 10월 30일 해외 VPN을 거친 외부 접속 시도가 탐지됐다고 보도했습니다. 1차 방어 시스템이 접속을 막았고, 운영사는 외부 연동 포트를 선제적으로 차단했습니다. 보도된 내용은 침입 *시도*이며 유출은 확인되지 않았습니다. 다만 보안 업계는 이런 서버가 장악되면 세대 내 카메라 도촬로 번질 수 있다고 지적했고, 2021년에는 638개 단지 약 40만 가구의 월패드 영상이 유출된 사건이 있었습니다.

결론은 하나입니다. **카메라 자체를 믿지 않아도 안전하게 운영되는 구조**를 만들어야 합니다. 카메라는 바깥 인터넷과 끊고, 영상을 보러 들어오는 입구는 하나로 모으고, 그 입구를 제대로 지키는 것입니다. 아래 점검표는 이 순서를 따릅니다.

## 점검표 1단계: 카메라에서 확인할 것은?

카메라 단계는 사용자가 바로 할 수 있는 일들입니다. 설치업체라면 신규 설치와 정기 점검 때 이 항목을 현장 기록에 남겨 두면 좋습니다.

1. **모델명과 지원 상태를 확인합니다.** 카메라 라벨의 모델명과 제조 연월로 제조사 고객지원 페이지를 찾아, 마지막 펌웨어 날짜와 지원 종료 여부를 확인합니다.
2. **초기 비밀번호를 바꾸고 카메라마다 다르게 둡니다.** 같은 비밀번호를 모든 카메라에 쓰면 한 대가 뚫렸을 때 전부가 열립니다.
3. **쓰지 않는 원격 기능을 끕니다.** 제조사 P2P 클라우드 연결, 원격 접속 앱 연동, UPnP 같은 기능은 녹화 시스템으로 영상을 보는 현장에서는 필요 없는 경우가 많습니다.
4. **펌웨어를 최신으로 올립니다.** 지원이 끝난 모델이라면 교체 계획을 세웁니다(아래 「구형 카메라는 당장 바꿔야 하나요?」 참고).

## 점검표 2단계: 네트워크에서 확인할 것은?

이번 점검에서 가장 많이 나온 문제는 "안전한 통신 프로토콜 미사용"(8개 제품)이었습니다. 카메라의 통신 방식은 사용자가 바꿀 수 없지만, 그 통신이 **어디까지 나가는지**는 네트워크에서 정할 수 있습니다.

1. **공유기의 포트 포워딩·UPnP 규칙을 지웁니다.** 카메라로 직접 들어오는 외부 경로를 없앱니다.
2. **카메라의 외부 인터넷 접속을 차단합니다.** 공유기의 외부 IP 차단(접근 제어) 기능으로 카메라가 바깥으로 나가지 못하게 합니다. ipTime 공유기 기준 절차는 [중국산 IP카메라, 인터넷 차단으로 격리하고 NOX를 이용해서 안전하게 쓰는 법](/blog/iptime-ip-camera-isolation-nox-vms.html)에 단계별로 정리해 두었습니다.
3. **영상을 보러 들어오는 입구를 녹화 시스템 하나로 모읍니다.** 원격에서 영상을 봐야 한다면 카메라가 아니라 NVR/VMS로 들어오게 합니다. 가능하면 포트 개방보다 VPN을 거쳐 들어오는 편이 공격 표면이 작습니다.
4. **카메라와 업무용 PC를 가능하면 다른 네트워크로 나눕니다.** 같은 망 안에 감염된 기기가 있으면 외부 차단만으로는 막을 수 없습니다.

이렇게 바꾸면 카메라와 녹화 시스템 사이의 통신은 현장 내부망 안에서만 오가고, 바깥에서 보이는 것은 녹화 시스템 하나가 됩니다. 그래서 다음 단계, 녹화 시스템의 보안이 전체 보안을 좌우하게 됩니다.

## 점검표 3단계: 녹화 시스템(NVR/VMS)에서 확인할 것은?

입구를 하나로 모았다면, 그 입구가 카메라보다 단단해야 의미가 있습니다. 녹화 시스템을 고르거나 점검할 때 확인할 항목과, NOX에서 각 항목이 어떻게 동작하는지 정리했습니다.

| 확인 항목 | NOX의 동작 |
| --- | --- |
| 초기 계정을 그대로 쓸 수 없는가 | 최초 로그인 때 비밀번호와 계정명 변경이 강제됩니다. 초기 설정을 마치기 전에는 화면뿐 아니라 API·실시간 영상·알림과 외부 ONVIF·RTSP 접속까지 모두 차단됩니다 |
| 약한 비밀번호를 막는가 | 9자 이상, 숫자·대문자·소문자·특수문자를 각각 1개 이상 포함해야 하며, 아이디와 같은 값·같은 문자 반복·키보드 순차 입력은 거부합니다 |
| 비밀번호 대입 공격을 막는가 | 연속 로그인 실패 시 계정이 자동으로 잠깁니다(기본 5회 실패 시 5분, 보안 설정에서 조정) |
| 자리를 비운 화면이 열려 있지 않은가 | 활동이 없으면 세션이 자동 종료됩니다(1~10분, 기본 10분) |
| 접속 구간이 암호화되는가 | 웹 접속은 HTTPS(TLS 1.2 이상)로 이뤄집니다 |
| 카메라 비밀번호가 평문으로 남지 않는가 | 카메라 비밀번호는 암호화해 저장하며, 주소에 섞여 있던 자격 정보도 걷어 내 암호화 보관합니다 |
| 볼 수 있는 사람과 카메라를 나눌 수 있는가 | 역할 기반 권한, 리소스 그룹, 카메라별 세부 권한으로 나눕니다. 일반 접속과 관리 접속도 분리됩니다 |
| 누가 무엇을 했는지 남는가 | 감사 로그를 SHA-256 해시 체인으로 묶어 위변조를 감지하고, 원격 syslog(TLS)로 외부 보관 서버에 보낼 수 있습니다 |
| 내보낸 영상이 유출돼도 안전한가 | 백업 영상을 AES-256-GCM으로 암호화하고 무결성을 검증합니다. 백업할 때 얼굴·사람·번호판을 가리는 비식별화도 할 수 있습니다 |

표의 항목은 NOX가 대응하는 국정원 영상처리기기 보안요구사항 10개 영역(식별 및 인증, 접근통제, 세션 관리, 감사기록, 데이터 보호 등)과 같은 축입니다. 공공 현장이 아니더라도 이 축으로 녹화 시스템을 점검하면 빠지는 항목이 적습니다. 자세한 내용은 [NVR/VMS 국정원 보안요구사항 V3.0 인증 가이드](/blog/nis-security-requirements-v3-guide.html)를 참고하세요.

NIS 보안 모드로 운영하는 장비에서는 관리 접속을 허용 IP 화이트리스트로 제한할 수 있습니다. 화이트리스트가 비어 있으면 장비 앞 로컬 화면에서만 관리 접속이 가능합니다.

## 구형 카메라는 당장 바꿔야 하나요?

현실적으로 모든 카메라를 한 번에 바꾸기는 어렵습니다. 「디지털 문단속」 기사는 지원이 끝났지만 성능에 문제가 없는 카메라라면 네트워크에서 완전히 떼어 SD카드 녹화용으로만 쓰라고 권합니다. 가정용 홈캠이라면 좋은 방법입니다.

여러 대를 녹화 시스템으로 관리하는 현장이라면 중간 단계가 있습니다. 카메라를 외부 인터넷에서 차단하고, 같은 내부망의 NOX가 ONVIF·RTSP로 영상을 받아 녹화하게 하는 것입니다. 외부에서 보이는 것은 NOX뿐이므로 카메라의 취약점이 바깥으로 직접 노출되지 않습니다. 다만 이 방법은 위험을 줄이는 것이지 없애는 것은 아닙니다. 내부망에 다른 감염 기기가 들어오면 카메라는 여전히 공격받을 수 있으므로, 지원이 끝난 카메라는 교체 일정을 함께 잡아 두세요.

교체할 때 번거로운 것은 카메라를 지우고 다시 등록하면서 설정과 기록이 끊기는 일입니다. NOX의 장치 교체 기능은 카메라 ID를 그대로 유지한 채 새 장치로 바꿔 줍니다. 교체 전에 새 장치의 연결을 미리 확인하고, 유지되는 설정 중 새 화각에 맞는지 다시 봐야 할 항목(마스킹 등)을 알려 줍니다. 그래서 구형 카메라를 한 대씩 순서대로 바꾸는 계획을 세우기가 쉽습니다.

폐기할 카메라는 기사 권고대로 공장 초기화를 하고, 완전히 버릴 때는 내부 메모리를 물리적으로 파기해 와이파이 정보와 남은 영상이 복원되지 않게 합니다.

## 관리사무소와 고객에게는 어떻게 설명할까요?

이번 같은 보도가 나오면 설치업체는 "우리 카메라도 위험한가요?"라는 문의를 받습니다. 이때 브랜드 이야기로 답하기보다 구조로 답하는 편이 정확하고 오래 갑니다.

> "카메라는 바깥 인터넷과 끊어 두었고, 영상은 녹화 서버 한 곳으로만 볼 수 있습니다. 그 서버는 초기 비밀번호를 쓸 수 없게 막혀 있고, 로그인 실패가 반복되면 잠기며, 누가 언제 접속해 무엇을 했는지 기록이 남습니다."

여기에 위의 점검표를 정기 점검 항목으로 붙이면 유지보수 계약의 근거가 됩니다. 녹화 누락, 오프라인 카메라, 디스크 상태 같은 운영 점검과 함께 보안 점검을 묶어 보고하면 고객이 보는 가치가 분명해집니다.

## 마치며

소비자원·KISA 점검이 보여 준 것은 특정 제품의 문제만이 아닙니다. 통신 암호화, 펌웨어 설정, 업데이트 지원처럼 사용자가 바꿀 수 없는 부분이 대부분의 카메라에 걸쳐 있다는 사실입니다. 그래서 카메라를 고르는 일만큼 **카메라를 어떤 구조 안에 두는지**가 중요합니다. 카메라는 바깥과 끊고, 입구는 녹화 시스템 하나로 모으고, 그 입구는 인증·잠금·세션·감사 기록으로 지킵니다.

NOX는 범용 x86 서버에 설치하는 NVR/VMS로, 기존 카메라를 그대로 쓰면서 이 구조를 만들 수 있습니다. 현장 구성에 맞는 에디션과 구성은 상담으로 안내해 드립니다.
